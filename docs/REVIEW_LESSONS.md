更新：2026-09-29。本文件分别整理 ICML 2026 与 ICDM 2026 的审稿意见，为下一版研究设计服务；**审稿人的判断、作者在 rebuttal 中的解释和已验证事实三者不等同**。会议反馈针对当时的投稿版本，不自动评价当前代码。研究任务见 [RESEARCH_PLAN.md](RESEARCH_PLAN.md)，相关论文见 [RESEARCH_REFERENCES.md](RESEARCH_REFERENCES.md)。

原始材料位于仓库外的工作区 `Papers/`（不会随此 Git 仓库发布）：`Papers/ICML2026/TabDAT_ Tabular Data Synthesis via Dependency-Aware Transformer _ OpenReview.mhtml`、`Papers/ICML2026/rebuttal.md`、`Papers/ICDM2026/review.md`。ICML 归档对应 [OpenReview 讨论页](https://openreview.net/forum?id=qCX3t6IqoS)。

## ICML 2026：审稿与最终决定

归档中有四位审稿人：vCq8、U6nu 给接受建议，7GQa、t519 给拒绝建议；最终决定为拒绝。最终决定文本明确提到：理论表述、论文写作、DP 论证／评价和基线覆盖仍不足。积极评价主要集中在合成质量、注意力建模和采样顺序；U6nu 特别认为顺序是论文中有价值的洞察，并建议降低 DP 在主张中的比重。

| 有用的意见与出处 | 下一版应怎样处理 | 当前对应状态 |
| --- | --- | --- |
| **理论主张过强**：最终决定指出，链式分解本身不把一般联合分布学习的最坏情况复杂度降到 `O(D²)`；“学习联合分布”和“保留全部依赖”也不宜写成两个独立数学困难。 | 删除无条件的复杂度降低断言，改研究“有限样本／容量／预算下，不同顺序的可拟合误差是否不同”；明确这是假设，不是链式法则的推论。 | [计划 M0、M2](RESEARCH_PLAN.md) 已转向可验证的顺序机制；论文表述待改。 |
| **顺序、W 与注意力偏置作用混淆**：7GQa、U6nu 质疑去除 W/M 时的采样顺序和固定顺序对照；7GQa 还质疑 W 的含义、顺序公平性和各组件必要性。 | 同一模型仅换采样顺序、各顺序分别匹配训练都要做；分别固定顺序比较有／无 W 注意力偏置，并记录 W 的稳定性。W 不宣称因果图；不能仅凭旧消融说它学到真实依赖。 | M0、M2 已列；实验未做。 |
| **泛化质量指标不足**：7GQa 要求 alpha-precision、beta-recall、C2ST、结构有效性；vCq8 问采样误差进入低密度区域后会怎样。 | 增加模式覆盖、可区分性、重复率、规则违反率和逐条件误差；区分真实数据中稀有组合与错误组合。rebuttal 中补充的数值是答辩证据，不自动等于新版本完整实验。 | M4 已有方向，统一真实数据测试时实施。 |
| **基线与容量覆盖**：7GQa 提到 TabDiff、REaLTabFormer、TabPFN 类方法；t519 提到 LLM／DP Transformer 方法。vCq8 要求考察模型规模；7GQa 要求更宽的表格。 | 按“与核心机制同构”及“代表不同模型家族”分层选基线，说明排除依据；报告参数量、计算预算和宽表结果。若不再主张 DP，单独的 DP 基线清单不必成为主实验轴。 | M3、M4 部分覆盖；具体基线清单待定。 |
| **DP 主张需要独立核验**：vCq8、7GQa 要求更实际的隐私预算、效用—隐私曲线及攻击审计；t519 质疑私有数据预处理统计量与端到端保证；最终决定又指出缺少 AIM 等 DP 基线。 | 新论文暂不把 DP 当主贡献。若保留正式 DP 结果，独立审计数据预处理、训练机制、会计、公开内容及基线；攻击实验是补充证据，不能替代形式保证。 | 当前计划暂缓 DP，M4 留有条件性审计任务。 |
| **呈现与可复现性**：U6nu 和最终决定指出占位文字、笔误与图示解释不足；vCq8 要求指标方向清晰。 | 提交前检查全文占位符、表格方向、图注、模型选择及可运行代码；把结论限制在指标真正支持的范围内。 | 待论文阶段落实。 |

需要特别保留的正面信号：U6nu 认为即使不把 DP 作为中心，合成质量和顺序机制仍值得研究；vCq8 对条件建模和实验结果评价较高。但接受建议并不能替代针对反对意见的机制证据。

## ICDM 2026：四份审稿报告

四位审稿人都认为当前方法的新意表达不够突出：#1、#3 倾向拒绝，#2、#4 给边缘评价。#2 承认实验覆盖与工程设计；#4 认可掩码训练对部分输入条件的动机。因此，下一版最值得保留的是“顺序可能是关键”，最需要重建的是“W 怎样带来可归因的额外贡献”。

| 有用的意见与出处 | 下一版应怎样处理 | 当前对应状态 |
| --- | --- | --- |
| **新意与消融不匹配**：#1、#3 认为是现有模块组合；#2、#4 指出 W/M 的消融收益小于顺序和注意力作用。 | 把主线从“模块组合”转成可证伪的顺序假说：先证明顺序间难度不同，再验证 W 的排序能力和注意力偏置作用。若 W 表现不够好，应如实承认并提出新排序机制，而非继续用旧消融支撑标题。 | M0、M2 对应；未验证。 |
| **固定链式分解与随机掩码训练关系不清**：#2 明确要求说明固定顺序还是任意顺序、掩码概率如何对应推理步骤。 | 明确输入 mask、损失目标、任务抽样分布和采样协议；增加顺序匹配训练与任意条件训练的受控比较。 | M1 已记录方案，尚未实现。 |
| **顺序启发式缺少推导与对照**：#2、#3 质疑“小加权入度≈低条件熵”及 W 的稀疏性、稳定性、方向性。 | 不直接把 W 权重解释为条件熵或 DAG 边；做受控数据、随机顺序分布、统计量排序、逐步条件误差和跨种子稳定性比较。 | M0、M2 对应。 |
| **平均指标掩盖失败，百分比表达夸大**：#2、#3、#4 要逐数据集结果；#2、#4 特别质疑近零分母的相对改善和“合成数据优于真实数据”。 | 报告每个数据集与种子的原始 TRTR／TSTR 结果、绝对差、区间；负 gap 只表示指定下游模型与划分中的观察值，需用非线性模型复核，不作普遍“优于真实数据”主张。 | M4 已列；论文表述待改。 |
| **评价和效率不完整**：#2、#3 要宽表、高阶依赖、覆盖、多样性、隐私攻击、训练与逐列采样成本。 | 统一协议下补足质量与成本；不要只给平均效用，不忽略顺序采样的 D 次 Transformer 调用。 | M4 已列；真实数据实验暂缓。 |
| **连续特征单高斯过于受限**：#3 指出多峰、偏态、有界、重尾数值难以由单高斯表示。 | 比较 Gaussian、GMM 和条件 DDPM 的逐列拟合、最终合成质量和成本；这些输出头本身不是顺序机制创新。 | 输出头代码已有人工检查，真实数据效果未验证。 |
| **DP 会计存在相互矛盾的评语**：#2 认为会计正确；#4 认为对 batch 的组合方式可能造成隐私开销误算。#3 也认为攻击与效率证据不足。 | 两种判断不能凭审稿票数决定。若仍作正式 DP 声明，独立核对实现、采样机制与会计假设，审计前不沿用旧保证措辞。 | DP 已从新主线移出；保留条件性任务。 |
| **复现与论文卫生**：#1、#3 提到代码／数据引用、模型选择与基线调参；#2 提到指标并列第一却写成独占最优、命名和笔误。 | 固定 checkpoint 规则、种子、训练预算、生成数量及基线调参；发布前逐项核对指标文字和代码可复现性。 | M0、M4 部分覆盖。 |

## 综合优先级与使用原则

1. **必须先解决的机制问题**：顺序难度、训练—采样协议、W 排序作用与注意力作用的可归因分离，以及链式法则不能自动带来复杂度改进的理论表述。
2. **必须补足的证据**：逐数据集／逐种子结果，直接质量和有效性指标，宽表与统一硬件成本，公平的顺序和输出头对照。
3. **有条件处理的方向**：若新稿不把 DP 当贡献，可简述它作为可选应用并避免正式隐私声明；若保留隐私保证，则必须另立完整的审计与基线协议。

不把 review 的每一条建议机械地变成新模块。优先级由新论文的研究主张决定；同样，也不能把 rebuttal 中尚未经新版本实验复核的解释当成已解决问题。
