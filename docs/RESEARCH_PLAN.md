## 研究主线

核心问题：在有限样本、模型容量和训练预算下，生成顺序如何影响条件分布的学习难度和合成质量？能否找到对指定模型有利的顺序？

分别验证三件事：（1）顺序之间有学习难度差异；（2）在控制训练与采样匹配后，这种差异影响质量；（3）TabDAT 的 W 与排序算法能找到有利顺序。第三点是待验证假设，不能从 W 的权重或低入度直接推出。W 是软注意力偏置，并非有无环保证的 DAG。

暂不把 DP 和跨表预训练作为新论文主线。条件生成与缺失列填补属于应用评估。单纯加入 diffusion、调整 mask 概率或组合已有模块，不单独构成核心创新。

## 任务清单

执行顺序：先定 M0 的实验规格并完成 M1 的人工数据检查；下一步单独讨论 M1.5 的损失设计。模块齐备后，先与用户确认可用数据及协议，再开展 M2–M4 的正式实验。候选掩码策略均已加入代码，是否进入正式实验由 M0 协议决定；条件生成／缺失列填补是可选应用，不阻塞顺序主线。

### M0：固定顺序机制实验协议（与 M1 接口设计同步）

- [ ] 设计两类实验：同一模型只改变采样顺序；各顺序分别匹配训练。明确两者支持的不同结论。
- [ ] 选定小维度受控分布：条件单峰而反向多峰、非线性关系、独立变量负对照；枚举或充分采样顺序。
- [ ] 预先确定数据划分、种子、训练预算、checkpoint 选择、样本数和主要指标；不依据测试集挑选顺序。
- [ ] 确定排序对照：W、固定、随机顺序分布、反向、简单统计量排序；必要时移植 PAFT 的排序策略。
- [ ] 定义“易拟合”的可观察量：逐步条件预测误差、联合质量与训练成本。区别条件熵与模型拟合误差。
- [ ] 指定每个对照的训练顺序来源：`prefix_next` 需要训练前已定的顺序；不能事后用同一次训练最终学到的 W 顺序冒充匹配训练。
- [ ] 区分两种问题：任意**整表生成顺序**，与固定规范次序下的任意**列子集查询**；不能把后者的性能称为前者的证据。

验收：完成可交给代码会话的实验规格，说明各实验能和不能支持的结论。

验收：每次仅改变一个实验因素，结果可追溯，旧基线可复现。

输出头实现备注：`gaussian` 保持默认；`gmm` 使用混合高斯 NLL；`ddpm` 使用标量条件噪声预测 MSE、100 步 cosine 日程，采样时每列只运行一次 Transformer、复用其条件向量进行多步去噪。分类头、独立概率掩码和排序逻辑未改。`dp=True` 暂仅支持原 Gaussian 路径，不将新输出头纳入未经审计的 DP 声明。核心环境规格见 `environment.yml`；真实数据及 GPU 实验须先确认数据与协议。

掩码设计备忘（已实现、未取得真实数据实验结论）：默认 `bernoulli_all` 的输入掩码与损失目标相同；采样第一步所有列均被掩盖。`fit()` 的默认独立掩码概率为 0.15，但 `model/main.py` 的训练示例显式传入 0.75；全掩码概率为 `p^D`（`D` 为列数），必须按实际实验配置判断覆盖程度。`prefix_next` 是训练时抽一个已定顺序中的位置，仅用真实前缀预测当前一列。给定任意已知列后，推理时按该顺序跳过已知列、填入第一列未知变量，是**采样规则**，仍需单独开发锁定已知列的采样接口；训练策略 `ordered_completion` 只是针对该类输入状态的额外对照，并非实现填补功能的前提。仅用前缀训练的模型即使将来能执行“跳过已知列”，也未必学过以非前缀列为条件的预测。此前把这种采样规则说成 MAC 的实现是不准确的；MAC 研究的是任意子集的边缘概率如何确定性分解和匹配训练任务分布。

损失设计备忘：撤回“新增掩码策略默认逐行除以目标列数”的暂定建议。当前按 batch 行数归一化的目标对每个被选中的列损失赋予相同系数，先保持它作为默认，以免在比较掩码策略时额外改变条件项权重；`prefix_next` 每行只有一个目标，逐行平均与当前目标本来也相同。逐行除以目标列数会降低大掩码数状态中每个条件项的权重，仅在明确要均衡不同掩码数量的总贡献时作为单独消融。若只需调整整体损失／梯度尺度，可使用不依赖单行掩码数的统一因子。分类／连续分别平均、DDPM 与 NLL 的相对权重留待 M3 依据逐列损失和骨干梯度研究。各策略的收益须与顺序本身的收益分离。

`mask_prob` 只控制 `bernoulli_all`；其余策略由各自的任务分布决定掩码，不读取该参数。

候选训练对照（代码已实现，正式实验是否使用尚未决定）：

- `ordered_completion`：均匀抽隐藏列数、再均匀抽隐藏列集合，只训练固定顺序中第一列未知变量的条件项；与 `uniform_count_all` 比较时，问题是集中训练实际条件填补路径是否改善该应用，而非能否实现填补功能。当前抽样分布仅是工程候选，后续可按应用查询分布重设。
- `canonical_subset`（MAC 启发，而非复现）：训练前固定规范**总次序** π₀；均匀抽查询子集大小、再均匀抽子集 E。仅训练 E 中最靠后的列在其余 E 列上的条件项；E 之外的列也作为输入掩盖。它覆盖任意子集查询的一类规范边，不等于实现了 MAC 的完整分解与按查询频率加权；当 E 是全表时，仍对应固定整表生成顺序 π₀，也不直接提供任意非前缀证据下的逐列条件采样。
- `random_permutation_next`：若真正研究任意整表生成顺序，则抽排列 σ 和步骤 t，训练 `p(x_{σ(t)} | x_{σ(<t)})`；不需要先固定 π₀。若限制为某依赖 DAG 的拓扑序集合，须先明确定义并验证 DAG；当前软矩阵 W 不能直接当作 DAG。

### M1.5：损失设计（下一步讨论，尚不改代码）

- [ ] 明确不同掩码策略下各条件项被抽中的频率，区分任务分布变化与损失归一化变化。
- [ ] 比较按 batch 行数、按目标项数量、分类／连续分别平均的含义与梯度尺度；先确定可复现的旧公式基线。
- [ ] 检查 Gaussian／GMM 的 NLL 与 DDPM 的去噪 MSE，决定是否需要可选权重；辅助损失仅在明确要解决的震荡或质量问题后设计。

验收：写出候选公式、预期影响与对照实验；确认后再修改代码。本轮未改变原有损失公式。

### M2：检验顺序和 W 的机制

- [ ] 测量不同顺序的条件误差与合成质量，报告 W 顺序的排名和随机顺序性能分布。
- [ ] 分离 W 的注意力偏置作用和排序作用；不以“同模型换序”替代“各顺序匹配训练”。
- [ ] 检查 W 在无关列、噪声、样本量变化和随机种子下的稳定性。
- [ ] 若现有 W 排序表现不足，定位失败原因，再设计利用条件拟合难度的排序方法。

验收：回答顺序是否重要、现有 W 是否找得准，以及收益来自 W 的哪种作用；允许否定结果。

### M3：输出头对顺序的影响与训练稳定性

- [ ] 使用 M1 的 Gaussian、GMM 和条件 diffusion 做顺序交叉实验；分类头先保持现状。
- [ ] 记录质量、训练成本和逐列采样成本。
- [ ] 检查分类／连续损失及骨干梯度后，再决定是否调整权重；diffusion 去噪损失不能直接与 NLL 数值比较。
- [ ] 使用预先固定的验证集 checkpoint 规则；针对明确问题再测试辅助损失，报告最终与所选 checkpoint 差距。

验收：解释强输出头如何改变顺序优势；不把已有的条件 diffusion 结构单独宣称为创新。

### M4：真实数据和论文证据

- [ ] 提供逐数据集、逐种子结果及区间；同时报告原始 TRTR／TSTR 分数和绝对差值。
- [ ] 检查高阶依赖、模式覆盖、重复率、真实与合成可区分性，以及条件填补。
- [ ] 加入较宽表格；同一硬件下比较参数量、训练时间、峰值显存、采样延迟和吞吐。
- [ ] 清楚定位 PAFT、MAC、DEformer、TabDAR；按论文的性能主张决定是否加入代表性 LLM 基线，或解释研究范围。
- [ ] 重写复杂度与依赖相关论述：链式分解本身不降低一般分布的最坏情况复杂度；将优势限定为指定模型、数据和预算下可检验的拟合难度差异。
- [ ] 如仍报告正式 DP 保证，先独立审计裁剪粒度、采样与会计、数据依赖预处理和发布内容。

验收：每项论文主张都有相应证据，不从平均值或单一消融推出超出实验范围的结论。

## 跨会话工作方式

1. 研究讨论会话负责文献、假设、实验设计、结果解释和验收；也负责更新本文件的研究决策与任务状态。
2. 代码会话每次只领取一张边界清晰的任务卡，开始前阅读本文件并检查 `git status`。它实现、验证并报告，不自行扩展研究问题或把实验结果写成论文结论。
3. 避免两个会话同时修改同一文件。代码会话完成后报告改动文件、检查结果、限制及提交状态；讨论会话复核后更新任务状态。若工作区已有正在进行的相同文件改动，先协调责任范围。
4. 区分“已实现”“已验证”“实验支持”“论文可主张”四种状态。

交给代码会话时，使用以下任务卡，避免口头讨论中尚未定论的想法被提前实现：

```text
任务目标：要实现的一个具体行为。
文件范围：允许修改的文件；其他未提交改动必须保留。
兼容约束：原有接口、checkpoint、默认行为及随机种子是否必须保持一致。
验收检查：需要运行的最小测试或可复现示例；成功标准。
交付说明：列出改动、验证结果、剩余限制、Git 提交状态；不要自行推送或发布。
```
