# TabDAT 研究计划

更新：2026-09-29。本文档只追踪研究问题、决策与下一步；实现细节见 [METHOD_NOTES.md](METHOD_NOTES.md)，文献用途见 [RESEARCH_REFERENCES.md](RESEARCH_REFERENCES.md)，基线协议见 [BASELINE_PROTOCOLS.md](BASELINE_PROTOCOLS.md)，审稿意见见 [REVIEW_LESSONS.md](REVIEW_LESSONS.md)。所有实验主张仍待验证；真实数据运行前须与用户确定数据和预算。

## 研究主线

核心问题：在有限样本、模型容量和训练预算下，生成顺序如何影响条件分布的学习难度和合成质量？能否找到对指定模型有利的顺序？

分别验证三件事：（1）顺序之间有学习难度差异；（2）在控制训练与采样匹配后，这种差异影响质量；（3）TabDAT 的 W 与排序算法能找到有利顺序。第三点是待验证假设，不能从 W 的权重或低入度直接推出。W 是软注意力偏置，并非有无环保证的 DAG。

暂不把 DP 和跨表预训练作为新论文主线。条件生成与缺失列填补属于应用评估。单纯加入 diffusion、调整 mask 概率或组合已有模块，不单独构成核心创新。

## 任务清单

执行顺序：先锁定数据／指标／checkpoint 协议和受控顺序实验，再研究预处理、损失与输出头交互。当前只完成工程接口和人工数据测试；候选策略不预设优劣。真实数据训练尚未启动。

### M0：固定顺序机制实验协议（与 M1 接口设计同步）

- [ ] 设计两类实验：同一模型只改变采样顺序；各顺序分别匹配训练。明确两者支持的不同结论。
- [ ] 选定小维度受控分布：条件单峰而反向多峰、非线性关系、独立变量负对照；枚举或充分采样顺序。
- [ ] 预先确定数据划分、种子、训练预算、checkpoint 选择、样本数和主要指标；不依据测试集挑选顺序。
- [ ] 确定排序对照：W、固定、随机顺序分布、反向、简单统计量排序；必要时移植 PAFT 的排序策略。
- [ ] 定义“易拟合”的可观察量：逐步条件预测误差、联合质量与训练成本。区别条件熵与模型拟合误差。
- [ ] 指定每个对照的训练顺序来源：`prefix_next` 需要训练前已定的顺序；不能事后用同一次训练最终学到的 W 顺序冒充匹配训练。
- [ ] 区分两种问题：任意**整表生成顺序**，与固定规范次序下的任意**列子集查询**；不能把后者的性能称为前者的证据。

验收：形成可复现的实验规格，说明各实验能和不能支持的结论。

### M1：完成核心掩码与顺序实验接口（当前工程任务）

- [x] 使采样顺序可显式指定，记录最近一次实际顺序、训练掩码配置；W 本来属于模型权重。实验运行级别的种子与多次采样顺序记录仍待实现。
- [x] 保留 `bernoulli_all` 旧行为，增加 `uniform_count_all`、`prefix_next`、`ordered_completion`、`canonical_subset` 和 `random_permutation_next`。有序策略要求训练前提供完整列排列；输入 mask 与损失目标 mask 分开定义。候选策略已实现不意味着被选为最终模型。
- [x] 将旧 DP 完整训练循环隔离至 `dp_training.py`；`fit(dp=True)` 保留兼容入口，新策略不接入未经审计的 DP 路径。
- [x] 分别记录分类与连续损失；保留现有 Gaussian 基线和 checkpoint 兼容性（人工 CPU 检查通过）。
- [x] 定义连续输出头的训练损失与条件采样接口，加入可选 GMM 和条件 DDPM；人工检查 Gaussian 旧行为及保存／加载兼容性。真实数据效果待验证。
- [x] 用人工数据验证默认掩码的固定种子行为、各策略目标不泄漏、显式顺序训练／采样和 checkpoint 元数据兼容。
- [ ] 在正式实验前补充运行级配置／种子记录；按 M0 协议验证真实数据上的可复现性。

验收：每次仅改变一个实验因素，结果可追溯，旧基线可复现。

掩码策略、输出头、当前损失公式和条件填补接口的细节集中在 [METHOD_NOTES.md](METHOD_NOTES.md)。

### M1.5：checkpoint 与评估协议（当前优先）

先确定用于**开发规则**的数据、划分和预算，再运行真实数据。旧稿九表用于可比性；首批候选 Adult、King、Covertype、Insurance 与受控人工表，新增宽表另议。候选尚待用户确认，保留官方／时间／分组划分；生成器及下游预测器的预处理仅用各自训练集拟合；分布指标内部的参考集变换按预先声明的定义执行。现有随机行划分工具不能替代特殊划分。

- [ ] 固定每表 train/validation/test、训练预算、随机种子、候选 epoch 间隔、每次生成行数和参考生成顺序。验证集可以用于选规则和 checkpoint；测试集只用于锁定协议后的报告。
- [ ] 首轮并列比较 `final`、最小**训练**条件损失和最小**验证**条件损失。建议以验证损失为首选：对同一模型和输出头，使用固定的验证掩码／顺序任务集计算 masked-only 逐列损失，减少随机抽掩码带来的选择噪声；不能拿 Gaussian NLL 与 diffusion MSE 直接跨头比较。
- [ ] 每个候选同时记录训练／验证逐列损失、W 导出顺序，以及固定参考顺序和实际顺序下的合成质量。先在开发集研究各规则与质量的相关性；若验证损失选得不稳，再预注册少量 checkpoint 的验证集合成质量择优规则，不能事后拼九项测试指标。
- [ ] 选择信号与报告指标分开。旧稿 ACC/AUC/F1、MAPE/EVS/R²、JS 距离/WD/关联误差保留可比性；新指标 α-precision／β-recall（naive 版本）和 LogisticDetection 可作为**质量诊断与后续优化依据**，但不自动纳入首轮 checkpoint 选择。另考虑约束有效率、成本和逐数据集区间；近零目标上的 MAPE、类不平衡和宽表尺度需单独说明。
- [ ] 对各基线记录实际采用的 checkpoint 与生成器预处理；官方协议与统一验证规则分开报告，不以论文是否选 `final` 作为 TabDAT 的选择理由。详见 [BASELINE_PROTOCOLS.md](BASELINE_PROTOCOLS.md)。

工程状态（尚非实验结论）：已实现训练集拟合变换后的验证数据输入、固定训练／验证任务库（含 DDPM 时间步与噪声）、逐列监测、`final`／`best_train`／`best_val` 独立保存及运行记录；人工 CPU 测试通过。训练预算不因选模提前结束；真实数据上的三种规则比较仍待用户确定数据和预算。详见 [METHOD_NOTES.md](METHOD_NOTES.md)。

现有评估已修正旧 MAPE/MSE、JS 距离/JSD 标签，关联误差改为独立列对平均绝对误差，分类 F1 改宏平均；旧结果不可不加标记地合并。新协议产物使用独立 `holdout_v1` 目录，不能把旧全量训练模型当作留出测试结果。人工数据上 dython 与 sklearn 路径已通过；额外指标接口已实现，但尽管两个顶层包已安装，`pip check` 仍报告多项缺失及 synthcity 与当前 Torch／NetworkX 的版本冲突，真实库导入和指标计算尚未通过。隐私评估入口暂停。

验收：用户确认数据、预算、主选择规则和报告指标后，才进行真实数据实验；本阶段不改训练损失。

### M1.6：损失设计（checkpoint 规则确定后）

- [ ] 明确不同掩码策略下各条件项被抽中的频率，区分任务分布变化与损失归一化变化。
- [ ] 比较按 batch 行数、按目标项数量、分类／连续分别平均的含义与梯度尺度；先确定可复现的旧公式基线。
- [ ] 检查 Gaussian／GMM 的 NLL 与 DDPM 的去噪 MSE，决定是否需要可选权重；辅助损失仅在明确要解决的震荡或质量问题后设计。

验收：用 M1.5 锁定的 checkpoint 规则分析逐列损失和指标冲突，写出候选公式、预期影响与对照实验；确认后再修改代码。目前未改变原有损失公式。

### M1.7：生成器预处理研究（M1.5 协议锁定后）

- [ ] 保留 TabDAT 当前默认 StandardScaler，系统比较 Standard、Gaussian quantile 和 MinMax；有明确长尾依据时再单独比较 log + scaler。每种变换均只在训练集拟合，并保存逆变换、缺失值和越界处理规则。
- [ ] 采用同一原始划分、种子、架构、输出头、掩码、训练预算和 checkpoint 规则，先做“仅改预处理”的消融，再与 Gaussian/GMM/DDPM 输出头交叉验证。记录尾部误差、逆变换后的真实量纲误差、离散化／异常值影响及生成约束，不只看标准化空间损失。
- [ ] 将生成器输入变换与下游评估器的固定变换分开；各基线可保留原生预处理，但不能让验证／测试数据参与拟合。根据结果再决定 TabDAT 的默认方案，不预先认定 quantile 一定优于 standard。

验收：给出逐数据集、逐输出头结果与边界条件；不把变换收益误判为顺序收益。

### M2：检验顺序和 W 的机制

- [ ] 测量不同顺序的条件误差与合成质量，报告 W 顺序的排名和随机顺序性能分布。
- [ ] 分离 W 的注意力偏置作用和排序作用；不以“同模型换序”替代“各顺序匹配训练”。
- [ ] 检查 W 在无关列、噪声、样本量变化和随机种子下的稳定性。
- [ ] 若现有 W 排序表现不足，定位失败原因，再设计利用条件拟合难度的排序方法。

验收：回答顺序是否重要、现有 W 是否找得准，以及收益来自 W 的哪种作用；允许否定结果。

### M3：输出头对顺序的影响与训练稳定性

- [ ] 使用 M1 的 Gaussian、GMM 和条件 diffusion 做顺序交叉实验；分类头先保持现状。
- [ ] 记录质量、训练成本和逐列采样成本。
- [ ] 检查分类／连续损失及骨干梯度后，再决定是否调整权重；diffusion 去噪损失不能直接与 NLL 数值比较。
- [ ] 沿用 M1.5 锁定的验证集 checkpoint 规则；在 M1.6 明确问题后再测试辅助损失，报告最终与所选 checkpoint 差距。

验收：解释强输出头如何改变顺序优势；不把已有的条件 diffusion 结构单独宣称为创新。

### M4：真实数据和论文证据

- [ ] 提供逐数据集、逐种子结果及区间；同时报告原始 TRTR／TSTR 分数和绝对差值。
- [ ] 检查高阶依赖、模式覆盖、重复率、真实与合成可区分性，以及条件填补。
- [ ] 加入较宽表格；同一硬件下比较参数量、训练时间、峰值显存、采样延迟和吞吐。
- [ ] 清楚定位 PAFT、MAC、DEformer、TabDAR；按论文的性能主张决定是否加入代表性 LLM 基线，或解释研究范围。
- [ ] 重写复杂度与依赖相关论述：链式分解本身不降低一般分布的最坏情况复杂度；将优势限定为指定模型、数据和预算下可检验的拟合难度差异。
- [ ] 如仍报告正式 DP 保证，先独立审计裁剪粒度、采样与会计、数据依赖预处理和发布内容。

验收：每项论文主张都有相应证据，不从平均值或单一消融推出超出实验范围的结论。

### 可选应用：条件生成／缺失列填补（不阻塞 M0–M4）

- [ ] 若纳入应用实验，增加“锁定给定列、按指定顺序跳过已知列并生成其余列”的采样接口；先评估 `bernoulli_all`／`uniform_count_all` 的条件质量。
- [ ] 对任意已知列集合分别测量条件目标误差与整体有效性。若现有训练的覆盖或容量分配不足，再评估上面的 `ordered_completion` 单目标训练对照；它不是必要算法，也不是 MAC 复现。
